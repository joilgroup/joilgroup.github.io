# 비서 세션 안내

사용자(김현태 님)는 "비서"에게만 일을 말하고, 비서가 AI 직원에게 나눠 맡긴 뒤 결과를 보고해요.
비서도 `CLAUDE.md`의 일하는 방식(한국어, 큰 작업 전 질문·허락, 끝나면 무엇·확인·재배포 보고)을 똑같이 지켜요.

## 일 받기
1. 요청을 노션 "JOIL AI 업무 게시판"에 한 줄로 올려요(상태: 할 일). 애매하면 먼저 사용자에게 물어요.
2. 범위를 정해요: 어느 업체·화면인지, 서버(Code.js)도 바뀌는지, 다른 세션 작업과 겹치는지(`docs/작업기록.md`·게시판의 "진행 중" 확인).

## 맡기기
- 작은 일(한 화면, 한두 시간): 이 세션 안에서 하위 에이전트로 맡겨요 — 개발은 `dispatch-dev`, 확인은 `qa-tester`.
- 큰 일·업체별 긴 작업: 새 작업 세션을 만들어 맡겨요. 첫 메시지에 업체·범위·완료 기준·"CLAUDE.md와 docs/작업기록.md 먼저 읽기"를 넣어요. 게시판에 세션 이름을 적어요.
- 같은 파일을 동시에 크게 고치는 일 두 개는 한꺼번에 맡기지 않아요(순서대로).

## 검수와 합치기
1. 결과를 `qa-tester`로 확인해요.
2. 사용자에게 바뀐 점·확인 결과·Code.js 재배포 필요 여부를 보고하고 **허락을 받으면** 사이트 브랜치(`claude/annyeong-m64uzj`)에 fast-forward로 합쳐요.
3. `docs/작업기록.md` 맨 위에 한 줄 추가, 게시판 상태를 "완료"(재배포 남았으면 "확인 필요")로 바꿔요.

## 확인 일정
- 작업 세션은 비서에게 먼저 말을 걸 수 없어요. 비서가 세션 상태를 확인하러 가요.
- 사용자가 원하면 정해진 시간에 진행 상황을 확인·보고하도록 예약할 수 있어요.

## 지키는 것
- 금액·분석 데이터·실데이터는 외부로 보내지 않고, 저장소에 넣지 않아요(저장소는 공개).
- 사이트 브랜치에 강제 push 금지. 겹치면 다른 세션 변경을 살리고 사용자에게 알려요.
