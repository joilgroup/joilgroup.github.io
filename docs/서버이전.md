## 결정과 이유 (사용자가 자리를 비워서 제가 정한 것)

1. **새 스키마 `joil`** 에 모든 새 표를 만들었어요 — 차량 위치 표(`public`)와 섞이지 않고, 되돌릴 때 `drop schema joil cascade` 한 줄이면 돼요. `joil` 은 REST API(PostgREST)에 열지 않아서 브라우저는 공개 키로도 못 읽어요.
2. **시트마다 표 하나, 칸 이름만 영어로** — 구글 시트 칸을 빠짐없이 옮기고, 비교·되돌리기를 쉽게. 날짜(`YYYY-MM-DD`)와 일시는 시트처럼 **글자**로 둠 — 화면·Code.js 가 글자로 비교해서 같은 응답을 내기 쉬워요. 오더 내용은 `json`(jsonb 아님): 칸 순서까지 시트에 적힌 그대로.
3. **새 서버는 Code.js 를 줄 단위로 옮긴 JS 한 파일**(`core.js`) — 같은 규칙·같은 오류 문구. node 와 Deno 둘 다에서 돌아서 테스트에서 지금 서버(목)와 **같은 요청을 보내 응답을 글자 단위로 비교**해요(`sb-parity`). Code.js 를 고치면 core.js 도 같이 고쳐야 해요(이름이 같아서 찾기 쉬움).
4. **DB 직접 연결**(함수 안 `SUPABASE_DB_URL`) — 저장을 트랜잭션 + 잠금(`pg_advisory_xact_lock`)으로. Code.js 는 저장 하나가 전체를 잠갔는데, 새 서버는 **같은 업체·같은 날짜끼리만** 줄 세워요(합차 때문에 탭이 아니라 업체 단위). 30초 넘게 차례가 안 오면 예전처럼 `BUSY|…` → 화면이 알아서 다시 보냄.
5. **15초 확인(`dispatch.stamp`)은 함수가 아니라 DB 함수(RPC) 직접 조회** — 공개 키 + 로그인 토큰 확인(`joil_stamps`). 함수 호출 수(무료 월 50만)에 안 들어가요. 바뀐 시각은 표 `disp_stamps`.
6. **세션**: Apps Script 캐시(6시간)+로그인 유지(30일)를 표 `sessions` 하나로. 토큰 원문은 저장 안 하고 SHA-256 만. 비밀번호 해시는 Code.js 와 같은 방식이라 **옮겨도 비밀번호 그대로**.
7. **사진 파일은 구글 드라이브에 그대로** — Supabase 무료 저장소는 1GB 라 인수증 사진(하루 수십~수백 장)이 금방 차요. 새 서버는 사진을 올리고/보여 줄 때 Code.js 의 내부 액션(`int.filePut·fileGet·fileTrash`)을 비밀값(`SB_GAS_SECRET`, 시험 복사 때 자동으로 양쪽에 저장)으로 불러요. **주소 좌표(카카오)도** 같은 방식(`int.geo`) — 카카오 키·주소 캐시가 구글 쪽에 있어서.
8. **화면 공개 설정**(견적 톤수 등)은 아직 구글 쪽 담당이라, 시험 복사 때 계산된 값(`PUBLIC_SETTINGS`)을 복사해 둬요.
9. **안 옮긴 메뉴(견적·일정·분석·공지 등)는 계속 Apps Script** — 전환 뒤에도 같은 로그인 토큰으로 쓰도록 Code.js 가 `SB_AUTH = '1'` 일 때 Supabase 토큰을 `joil_whoami` 로 확인(5분 캐시).
10. **갈림길은 묶음 하나(`'dispatch'`)** — 로그인과 배차는 같은 세션·같은 데이터라 따로 옮기면 꼬여요. 한 기기에서 먼저 시험하려면 주소 끝에 `#sb-on`(끄기 `#sb-off`).
11. **시험 복사는 매번 표를 비우고 처음부터** — 여러 번 눌러도 중복이 안 생기고 코드가 단순해요. 전환 뒤(`props.SB_LIVE = '1'`)에는 DB 가 비우기를 거부해서 실수로 덮어쓰지 않아요.
12. **계정 이름 바꾸기**의 "직원 목록(일정) 이름도 같이" 는 일정이 아직 구글 쪽이라 새 서버는 계정 이름만 바꿔요 (일정 옮길 때 같이).
13. **Supabase 에 실제로 적용(표 만들기·함수 배포)은 하지 않았어요.** 맡긴 일에는 있었지만, 운영 프로젝트에 무언가를 만드는 건 사용자가 돌아와서 한 번 보고 하는 게 안전하다고 판단했어요. 대신 **같은 SQL·같은 함수 코드를 이 컴퓨터의 시험용 Postgres·Deno 에서 끝까지 돌려 확인**했어요(아래). 적용은 "돌아오면 할 일" 2번, 명령 몇 줄이에요.

## 표 설계 (스키마 `joil`)

| 표 | 구글 시트 / 스크립트 속성 | 비고 |
|---|---|---|
| `accounts` | 계정 | 비밀번호 해시·솔트 그대로 |
| `sessions` · `login_fails` | (캐시 `S_…` · `LF_…` · 속성 `RT_…`) | 토큰은 해시만 |
| `props` | 속성 `SETTINGS`(→`PUBLIC_SETTINGS`)·`DISP_MUST_…`·`DISP_RATES_V2` | + `GAS_URL`·`GAS_SECRET`·`SB_LIVE` |
| `disp_orders` | 배차오더 | `data` = 오더 JSON · `ord` = 시트 줄 순서 |
| `disp_trucks` | 배차호차 | `rev`·`cost` = 매출·매입 직접 입력 (분석 권한만 응답) |
| `receipts` · `place_photos` | 인수증 · 상차지사진 | 드라이브 파일 ID 만 |
| `drivers` | 기사풀 | 생년월일은 협력사에 안 보냄 |
| `loading_places` · `dest_book` | 상차지 · 하차지주소록 | 업체 칸 빈 값 = 쿠팡부자재 |
| `disp_rates` · `center_map` | 배차단가표(세로형) · 센터도착 | 예전 가로형 '배차단가'는 복사 전에 Code.js 가 세로형으로 옮김 |
| `center_notes` | 도착지특이사항 | |
| `disp_tabs` · `disp_prices` · `disp_codes` · `disp_stamps` | 속성 `DISP_TABS_`·`DISP_PRICE_`·`DISP_CODES_`·`DST|…` | |

권한 규칙은 서버(core.js)가 Code.js 와 똑같이 지켜요: 매출·매입(`rev`·`cost`)은 분석 권한자만, 회차비·대기료·운송료지원은 분석 권한자와 협력사(보기만), 협력사는 배정된 탭만·내부 공지 없음·합차 링크코드 없음(`dispScrub`), 월별 기록·단가표 수정·견적 등은 협력사 막힘.

## 시험 방법 (실제 프로젝트를 더럽히지 않게)

- `node tests/run.js sb` — 이 컴퓨터에 **빈 Postgres 를 잠깐 띄워**(`tests/sb/pg.js`) 마이그레이션 004~006 을 그대로 적용한 뒤:
  - `sb-parity`: 같은 요청을 지금 서버(Code.js 목)와 새 서버에 보내 **응답이 같은지** 65가지 (붙여넣기·전체/부분 저장·합차 전파·협력사 제한·기사 링크·오더 고치기/공지/복사/옮기기/지우기·월별·탭·단가·코드·특이사항·단가표·하차지·상차지·기사 풀·권한 오류 문구).
  - `sb-copy`: Code.js '시험 복사'를 끝까지 → 두 번 눌러도 중복 없음 → **옮긴 계정 비밀번호로 새 서버 로그인** → 시트에서 보던 것과 같은 화면 데이터 → 비교 도구가 다른 곳(호차 수·매출·매입)을 짚는지 → 전환 뒤 덮어쓰기 거부.
  - `sb-auth`: 잠금·로그인 유지·임시 비밀번호·비밀번호 변경·계정 관리·사용중지·RPC(공개 키)·공개 키로 표 못 읽음.
  - `sb-deno`: 실제 Supabase 함수 입구(`index.ts`)를 **Deno 로 띄워** text/plain 요청·CORS·gzip 확인.
  - Postgres/Deno 가 없는 컴퓨터에서는 "건너뜀"으로 통과해요. 다른 DB 로 돌리려면 `JOIL_TEST_DB=postgres://…`(운영 `joil` 스키마에는 쓰지 마세요).
- 실제 Supabase 에서 시험하고 싶으면: 마이그레이션 파일의 `joil` 을 `joil_test` 로 바꿔 한 번 더 적용하고, 함수 비밀값 `JOIL_SCHEMA=joil_test` 로 둔 **두 번째 함수**(예: `joil-test`)를 배포하면 운영 표와 섞이지 않아요.
- 지금 테스트(`node tests/run.js`)도 모두 통과해요.

## 전체 전환 순서 (4단계)

## 전환 뒤 새 기능 (2026-11-21~)

### 변경 이력 (마이그레이션 008)
- DB 트리거가 배차 오더·호차(금액 포함)·단가표·특이사항·월별 단가·차도리 코드·탭·센터도착·계정을 바꿀 때마다 `joil.audit` 에 남겨요(바뀐 칸만 `{칸: [전, 후]}`). '누가' = core.js 가 요청마다 `set_config('joil.who')`.
- 호차·단가표·특이사항은 저장이 '다 지우고 다시 넣기'라 지운 줄을 `audit_stash` 에 잠깐 두고 다시 넣은 줄과 비교, 안 돌아온 줄은 트랜잭션 끝(지연 트리거)에 '삭제'로.
- 화면: 배차 호차 ⋯ → 변경 이력(`dispatch.history`, 그 호차 + 실린 오더) · 관리자 → 변경 이력(`admin.audit`). 금액 칸은 분석 권한자만, 협력사는 못 봄, 비밀번호는 '(바뀜)'만.
- 용량: 하루 저장 수백 번 × 바뀐 칸만 약 300B ≈ 하루 100KB 안팎 → 1년 약 40MB. 1년(400일) 넘은 건 로그인 때 가끔 지움.
- 적용 전 백업: 스키마 `joil_bak_20261121`(joil 표 전부 복사, 줄 수·금액 합계 같음 확인).
- 되돌리기: `drop trigger audit_row on joil.disp_orders;` … (008 파일의 trigger 이름 전부) → `drop table joil.audit, joil.audit_stash; drop function joil.audit_who, joil.audit_diff, joil.audit_key, joil.audit_skip, joil.audit_money, joil.audit_fresh, joil.audit_put, joil.audit_ref, joil.audit_stash_del, joil.audit_stash_ins, joil.audit_stash_end, joil.audit_row;` 데이터는 안 바뀌어서 표를 되돌릴 필요 없음. 백업 스키마는 2주 뒤 문제없으면 `drop schema joil_bak_20261121 cascade`.

### 실시간 반영 (마이그레이션 009)
- 저장으로 `disp_stamps`(바뀐 시각)가 바뀌면 트리거가 Supabase Realtime 으로 신호만 보냄(`realtime.send`, 내용 = 바뀐 시각 숫자뿐). 채널 이름 = 비밀값(`props.RT_SECRET`)으로 만든 해시(`joil.rt_topic`) — 화면은 로그인 확인을 거친 `joil_stamps` 응답의 `topics` 로만 알아요(협력사는 자기 탭만).
- 화면(`rtWatch`·`rtOpen`·`rtKick`): 웹소켓 직접(라이브러리 없음) → 신호가 오면 0.3초 뒤 확인 → 바뀌었으면 받아서 "내가 안 고친 칸만" 합침(예전 규칙 그대로). 저장 중·입력 중이면 끝난 뒤에. 연결돼 있으면 확인은 2분에 한 번, 끊기면 15초(예전 그대로)·다시 연결은 1초→최대 60초 간격.
- 무료 한도: 동시 접속 = 켜 둔 배차 화면 수(10대 안팎, 한도 200) · 메시지 = 저장 하루 약 1,000번 × 같은 날짜 보는 화면 약 5 = 하루 5천 → 월 약 15만(한도 200만). 15초 확인(DB 조회)은 화면당 시간 240번 → 30번으로 줄어요.
- 운영에서 확인: 가짜 업체 채널로 붙어 바뀐 시각을 넣으면 약 2초 뒤 신호 도착(2026-11-21).
- 되돌리기: `drop trigger rt_stamp on joil.disp_stamps;` → 화면은 신호가 없으니 15초 확인으로 돌아가요. `joil_stamps` 는 005 내용으로 다시 만들어도 되고 그대로 둬도 돼요(topics 를 더 줄 뿐).

## 돌아오면 할 일 (사용자)

> 1~4 는 **사이트에 영향 없음**(시험). 5 부터가 실제 전환이에요. Code.js 재배포가 **필요해요**(1번).

1. **Code.js 재배포** — 이 브랜치의 `apps-script/Code.js` 를 Apps Script 에 붙여넣고 "새 버전" 배포. 새로 생긴 건 관리자만 누르는 버튼과 꺼진 기능뿐이라 지금 동작은 그대로예요. (사이트 브랜치에 아직 안 합쳤으니, 화면의 "서버 이전 준비" 버튼은 6번 전까진 안 보여요 — 그 전에 해 보려면 이 브랜치를 사이트에 합칠지 저에게 말해 주세요. 갈림길 기본값은 꺼짐이라 합쳐도 동작은 같아요.)
2. **Supabase 에 표·함수 만들기** (저에게 "적용해"라고 하면 제가 관리 API 로 해요) — 순서대로:
   - SQL: `supabase/migrations/004_joil_core.sql` → `005_joil_stamp_rpc.sql` → `006_joil_copy_tools.sql` (SQL Editor 에 붙여넣거나 관리 API `database/query`)
   - 함수: `supabase functions deploy joil --no-verify-jwt` (폴더 `supabase/functions/joil` 의 `index.ts`+`core.js`) 또는 관리 API `functions/deploy?slug=joil` (`verify_jwt: false`)
3. **시험 복사** — 관리자 → API 키 → 서버 이전 준비 → "시험 복사" (몇 분 · 시트는 안 바뀜) → "비교"로 이번 달·지난달이 "모두 같아요"인지.
4. **한 기기에서 시험** — `config.js` 에 아래 세 줄을 넣고(사이트 반영 필요), 시험할 기기에서만 주소 끝에 `#sb-on` → 다시 로그인 → 배차 화면 확인. 끝나면 `#sb-off`.
   ```js
   SB_FN: 'https://etvpifkfyrxvvpqqrsza.supabase.co/functions/v1/joil',
   SB_REST: 'https://etvpifkfyrxvvpqqrsza.supabase.co',
   SB_ANON: '공개 키(anon / publishable)',   // 공개용 키라 저장소에 있어도 됨
   ```
   - 시험하는 동안 이 기기의 배차 저장은 **Supabase 에만** 가요(시트엔 안 감). 시험용 날짜에서만 해 보고, 끝나면 3번 시험 복사를 다시 하면 시트 기준으로 돌아가요.

   3. SQL 한 줄: `insert into joil.props values ('SB_LIVE','1') on conflict (key) do update set value='1';` (이제 시험 복사로 덮어쓰기 불가)
   4. `config.js` 에 `SB_ROUTE: 'dispatch'` → 사이트 반영 → 모두 다시 로그인
   5. 기사 사이트 저장소의 `driver-site/index.html` 의 `API_URL` 을 `SB_FN` 주소로 바꿔 올리기 (예전 기사 링크도 그대로 열려요 — 링크 코드가 같이 옮겨져서)

## 되돌리는 방법

- **전환 전**(1~4번 중): `config.js` 에서 `SB_ROUTE` 를 빼거나 기기에서 `#sb-off` → 바로 예전 그대로(시트가 원본이라 잃는 것 없음). Supabase 쪽을 지우려면 `drop schema joil cascade; drop function public.joil_stamps, public.joil_whoami, public.joil_copy, public.joil_counts, public.joil_summary, public.joil_dump, public.joil_prop_set, public.joil_copy_tables;` 와 함수 `joil` 삭제.
- **전환 뒤**: `SB_ROUTE` 를 빼면 화면은 바로 Apps Script 로 돌아가지만, **전환 뒤에 저장한 배차는 Supabase 에만 있어요.** 이때는 "조일 Supabase 백업" 파일(매일 밤)에서 필요한 날짜를 시트로 옮겨야 해요 — 자동으로 되돌리는 도구(Supabase → 원본 시트)는 아직 없어요(다음 할 일 후보). 그래서 전환 첫 주는 문제가 생기면 바로 알려 주세요.
- `SB_AUTH` 는 스크립트 속성에서 지우면 꺼져요.
